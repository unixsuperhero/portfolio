# Desktop app

`apps/desktop` is a Wails v3 shell around the same packages the CLI tools use. It shows
the library, dashboards (portfolios as homepages), projects with their services and
ports, reminders, and pull requests; it opens links in real browser windows; and it has a
built-in terminal. Nothing in it talks to SQLite directly: everything goes through
`@portfolio/api`, which the app starts as a sidecar.

```text
┌──────────────── Portfolio.app (Go, Wails v3) ────────────────┐
│ main window  wails://localhost/  ← React frontend (embedded) │
│   /health, /api/*  ── proxy.go ──►  bun packages/api  :4388  │──► portfolio.sqlite
│ PtyService      creack/pty ── events pty:data / pty:exit     │
│ BrowserService  one WKWebView window per URL                 │
│ NativeService   reveal, open, clipboard, notification        │
│ SidecarService  spawn or adopt the API, watchdog, shutdown   │
└──────────────────────────────────────────────────────────────┘
```

The contract every part was built against is [apps/desktop/CONTRACT.md](../apps/desktop/CONTRACT.md).

## Running

```bash
cd apps/desktop
wails3 dev            # vite + Go with reload
wails3 task build     # bin/desktop
wails3 task package   # bin/desktop.app, ad-hoc signed
```

The Go toolchain is pinned in `go.mod` (`toolchain go1.25.1`), so an older system Go
downloads it on first build. The frontend is a bun workspace member: run `bun install`
at the repo root once.

Run the app from the `.app` bundle, not the bare binary, when you need the in-app
browser to open `http://` sites: the bundle's `Info.plist` carries the App Transport
Security exceptions.

## What runs where

| Concern | Where | Why |
|---------|-------|-----|
| API calls from the page | `proxy.go` forwards `/health` and `/api/*` to `127.0.0.1:4388` | the page is a secure context on `wails://localhost`, so WebKit blocks plain-http requests, and the asset server strips `Content-Length`, so the proxy buffers bodies first |
| Wails detection | `frontend/src/lib/wails.ts`, from the page URL | `window._wails` only exists once the runtime module has evaluated |
| Bindings and events | `frontend/bindings/portfolio-desktop/` generated by `wails3 generate bindings` | the runtime is imported eagerly in `main.tsx` so Go's `ExecJS` and events are not queued forever |
| Terminal | `frontend/src/terminal/` (vendored libghostty wasm adapter, MIT) + `pty.go` | bytes travel as base64 on `pty:data`; the surface renders to a canvas |
| Sidecar | `sidecar.go` | adopts a running API on 4388, else spawns bun; a 10s watchdog respawns after three failed health checks |

## Data added for the desktop

```js
const card = { kind: "query" | "tasks" | "reminders" | "ports" | "clock" | "note" | "services" | "prs", config: {} };
const settings = { home_portfolio_id: 3 };                      // GET /api/home renders it
const task = { recurrence: "daily" | "once", reminders: [{ at: "08:30" }], completed_today: true, streak: 4 };
const reminder = { title: "Call the dentist", recurrence: "once", at: "2026-09-24T09:00", task_id: null };
const project = { services: { runner: "bun", scripts: { dev: "…" } }, ports: [/* listeners in this dir */] };
const pr = { state: "open", checks_summary: "success", watched: true, ignored_checks: ["codecov/*"], source_dir: "/Users/me/work/carrot" };
const settings = { github_dirs: ["/Users/me/work/carrot", "/Users/me/proj"] };   // gh runs from each; empty = the API's own cwd
```

The `tasks` card shows active tasks with nested subtasks and completion checkboxes. Completion checkboxes on tasks and reminders draw a check and settle the title; a daily task or reminder with a streak of two or more days shows an `N-day streak` count that ticks up when it advances, and a list whose entries are all complete ends with an "All done today." line. Due-reminder toasts slide in and settle out on Done. Each task links to its task page. Note cards support GitHub-flavored Markdown and a plain-text Markdown editor. Widget bodies and tile cards use the same horizontal padding as query rows.

Reminders are independent records with their own schedule and completion history. The Reminders form defaults to **No task**; selecting a task is optional. Creating a reminder does not create a task or a Library item. Completing a linked reminder does not complete its task. Existing task-linked reminders and their completion history migrate when the database opens.

Single and bulk reminder deletion use an in-app confirmation dialog. Cancel or Escape keeps the reminders; Confirm delete removes only the listed reminders. This avoids `window.confirm`, which the macOS webview does not implement.

See [data-model.md](data-model.md) for the full shapes and
[packages/api.md](packages/api.md), [packages/github.md](packages/github.md) for the routes.

## Testing the real app from a script

Build with the `mcp` tag and the app exposes the Wails MCP tools (page eval, DOM
queries, clicks, typing, bound-method calls) on `WAILS_MCP_PORT`:

```bash
cd apps/desktop
go build -tags mcp -o bin/desktop-mcp . && cp bin/desktop-mcp bin/Portfolio.app/Contents/MacOS/desktop
WAILS_MCP_PORT=9099 bin/Portfolio.app/Contents/MacOS/desktop &
curl -s http://127.0.0.1:9099/          # {"endpoint":".../mcp","tools":16}
```

Then POST JSON-RPC (`initialize`, `tools/call`) to the endpoint. The page-side bridge in
`frontend/src/lib/mcp-bridge.ts` makes the eval callback work inside WebKit; without it
every tool times out.

## Known gaps

- The ANSI palette comes from libghostty's defaults; the theme only sets foreground, background, cursor, and selection.
- Browser windows have no toolbar: close them from the window, or through `BrowserService.Close`.
- `pf-docs push` still targets the old server on 4387 (`/api/documents` is not in the new API).
- Native notifications use `osascript`, so they appear as "Script Editor" until the app is signed and packaged.
